## 5. Fix: le card nel pannello "mostra tutti i veicoli" vengono tagliate al passaggio del mouse

File: `src/app/globals.css` (regole `.garage-extra`, `.garage-extra-inner`, cercare `garage-extra` nel file) e `src/components/home/GarageSection.tsx`.

Causa: `.garage-extra-inner { overflow: hidden; }` è permanente. `overflow:hidden` **serve** durante l'animazione di apertura/chiusura (il trucco `grid-template-rows: 0fr → 1fr` su `.garage-extra` ha bisogno che il contenuto sia clippato mentre la riga cresce da altezza 0, altrimenti si vede uno "strappo" di contenuto durante l'animazione). Va quindi mantenuto **solo mentre l'animazione è in corso**, e rimosso (o messo a `visible`) una volta che il pannello è completamente aperto, così le card possono "fluttuare" sopra senza essere tagliate.

Implementazione consigliata: aggiungi in `GarageSection.tsx` uno state locale (es. `const [extraAssestato, setExtraAssestato] = useState(false)`) e un listener `onTransitionEnd` sul div `.garage-extra` che, quando la proprietà transizionata è `grid-template-rows` **e** `espanso === true`, imposta `extraAssestato = true`; quando si richiude (`espanso` torna `false`), rimetti `extraAssestato = false` immediatamente (non aspettare la fine della transizione di chiusura, altrimenti il contenuto "sborda" mentre il pannello si sta ancora richiudendo). Applica poi una classe modificatrice su `.garage-extra-inner` tipo `garage-extra-inner--assestato` che in CSS fa `overflow: visible` (mentre la regola base resta `overflow: hidden`).

Verifica alla fine: apri il pannello, aspetta che l'animazione finisca, passa il mouse su una card nell'ultima riga — la card deve inclinarsi/ingrandirsi liberamente senza che il bordo del pannello la tagli. Poi richiudi il pannello e verifica che l'animazione di chiusura resti pulita (nessun contenuto che sborda mentre si accorcia).

## 9. Distanza officine: calcolo reale al posto di "0 km" hardcoded

File principale: `src/app/prenotazioni/page.tsx`.

**Causa del bug** (verificata, non è un'ipotesi): il backend (`GET /officina/all`, gestito da `Backend/src/officina/officina.service.ts` → `findAll()`) non restituisce mai un campo `distanza_km` — nessun calcolo esiste, né lato client né lato server. Il frontend fa semplicemente `distanza_km: parseFloat(String(o.distanza_km ?? 0))` (riga 53), quindi il fallback `?? 0` scatta sempre. La geolocalizzazione dell'utente viene già acquisita (`navigator.geolocation.getCurrentPosition`, dentro `usaGps()`, righe ~282-295) ma oggi serve solo a centrare la mappa Leaflet (`mapRef.current?.setView(...)`, riga 290) — non viene mai confrontata con le coordinate delle officine, che invece sono già disponibili in `o.lat`/`o.lng` (righe 59-60, con fallback a Milano se il backend non ha coordinate).

Implementazione (**tutta frontend, nessuna modifica al backend**):

1. Aggiungi una funzione haversine pura, ad esempio in un nuovo file `src/lib/geo.ts`:
   ```ts
   export function distanzaKm(lat1: number, lng1: number, lat2: number, lng2: number): number {
     const R = 6371;
     const dLat = ((lat2 - lat1) * Math.PI) / 180;
     const dLng = ((lng2 - lng1) * Math.PI) / 180;
     const a =
       Math.sin(dLat / 2) ** 2 +
       Math.cos((lat1 * Math.PI) / 180) * Math.cos((lat2 * Math.PI) / 180) * Math.sin(dLng / 2) ** 2;
     return R * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
   }
   ```
2. In `prenotazioni/page.tsx`, tieni in uno state la posizione utente (es. `const [posUtente, setPosUtente] = useState<{lat:number; lng:number} | null>(null)`), popolata sia da `usaGps()` (aggiungi `setPosUtente({lat: pos.coords.latitude, lng: pos.coords.longitude})` accanto al già esistente `setView`) sia, se possibile, tentata automaticamente al mount della pagina con lo stesso `navigator.geolocation.getCurrentPosition` (permesso browser permettendo).
3. In `normalizzaOfficina` (o subito dopo, quando hai sia le officine che `posUtente`), calcola `distanza_km` con `distanzaKm(posUtente.lat, posUtente.lng, o.lat, o.lng)` invece di leggere il campo inesistente dal backend. L'ordinamento già esistente (`.sort((a,b) => a.distanza_km - b.distanza_km)`, riga 279) continua a funzionare invariato.
4. **Gestisci il caso senza geolocalizzazione** (permesso negato, browser senza supporto, o non ancora richiesta): non mostrare "0 km" (sarebbe un bug travestito da fix) — mostra invece un placeholder tipo "Distanza non disponibile" o nascondi il badge km finché `posUtente` è `null`, sia nella card lista (riga ~493) sia nel pannello di dettaglio (riga ~609).
